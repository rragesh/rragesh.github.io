Autonomous docking: finding the way back to charge

Ingeniarius · Coimbra, Portugal

A robot that can patrol on its own also needs a way to return to its charger. This project built and tested that return-to-charge routine in simulation.

The quiet problem behind an autonomous patrol

Imagine a robot halfway through its patrol when its battery starts to run low. Finding the way back to a charging station is part of keeping that robot useful throughout its operating cycle.

The STOP project used a small team of robots to patrol a single floor. My task was to develop the software routine that would take a robot to a charging station when its battery fell below a chosen threshold.

Turning a charging request into a journey home

The routine identified the nearest charging station and passed its location to the robot’s navigation software. Once the robot docked, it returned its charging status so the rest of the system could tell what had happened.

I used ROS—the Robot Operating System, a framework that connects robot software components—to fit the routine into the existing application. A ROS service provided the request-and-response interface, while the ROS navigation stack handled travel to the station.

Testing the complete sequence

The application was developed and successfully tested in Gazebo, a virtual environment for simulating robots. That made it possible to exercise the return-to-charge sequence as a connected workflow.

The useful result was a routine that linked battery state, navigation, docking, and charging feedback. It addressed an everyday operational need: giving the robot a defined way to stop working and recover its energy.
